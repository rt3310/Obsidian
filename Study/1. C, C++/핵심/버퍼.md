```c
int main() {
	int num;
	char c;
	
	printf("숫자를 입력하세요 : ");
	scanf("%d", &num);
	
	printf("문자를 입력하세요 : ");
	scanf("%c", &c);
	return 0;
}
```
성공적으로 컴파일 했으면
```
숫자를 입력하세요 : 1
문자를 입력하세요 :
```
실행해보면 문자 입력을 무시하고 넘어가는 것을 볼 수 있다. 왜그런걸까?

컴퓨터는 버퍼에 데이터를 저장하고 한번에 처리한다.
많은 버퍼 중에서도 키보드의 입력을 처리하는 버퍼는 입력 버퍼, 혹은 `stdin`(입력 스트림)이라고 부른다.

즉, 키보드로 입력하는 정보는 일시적으로 `stdin`에 저장되었다가 나중에 입력이 종료되면 한꺼번에 처리를 하는 것이다.

그런데, 컴퓨터가 우리가 입력을 종료했는지 어떻게 알까? 바로 엔터이다.
즉, `\n`(개행문자)를 '입력을 종료했으니 버퍼에 있는 내용을 처리해라' 라는 뜻으로 받아들인다.

하지만, 컴퓨터는 `\n`까지 버퍼에 저장하게 된다. 즉, 우리가 1을 쓰고 엔터를 치면 `1\n`이 저장되는 것이다.

그럼 위 코드에서
```c
scanf("%d", &num);
```
은 `stdin`에서 숫자 데이터만 얻어온다는 의미로, ' ', '\n', '\t'를 만날 때까지 데이터를 얻어온다.
여기서 ' '는 띄어쓰기 한 칸을 의미한다. 또한 `\t`는 탭 문자이다.

참고로, `%d` 계열의 것들, 즉 수를 입력받는 형식은 수가 아닌 데이터가 와도 입력을 종료해 버린다. 즉, `a`를 입력했다면 `num`에는 아무런 값이 들어가지 않아 치명적인 결과를 야기할 수 있다.
뿐만 아니라 수 데이터를 입력받는 형식의 경우 처음부터 공백문자가 나타나면 수가 나타날 때까지 입력을 계속 받게 된다. 다시 말해, 수를 입력 받는데 엔터를 아무리 쳐도 숫자를 치기 전까지 넘어가지 않는다)

그럼 `scanf`가 공백문자(' ', '\n', '\t')를 만나기 전까지 `stdin`에서 데이터를 가져간 후 버퍼에서 삭제해버린다. 그럼 `num`에 1을 저장한 후 버퍼에는 `\n`만 남게 된다.

그 다음
```c
scanf("%c", &c);
```
를 실행하게 되는다, `%c`는 이유를 불문하고 `stdin`에서 딱 한 개의 문자만을 가져오게 된다. 만약 `stdin`에 아무것도 없다면 사용자 입력을 기다리고 있겠지만 `stdin`에 무언가가 있다면 그것을 가져온다.
그런데 버퍼에 `\n`가 남아있기 대문에 `scanf`는 이를 `c`에 저장하게 된다.

### `%s`로 scanf에서 받을 경우
```c
#include <stdio.h>
int main() {
	char str[30];
	int i;
	
	scanf("%d", &i);
	scanf("%s", str);
	
	printf("str : %s", str);
	
	return 0;
}
```
성공적으로 컴파일 했다면
```
1
asdfasfasdf
str : asdfasfasdf
```
`%c`와는 달리 `%s`의 경우 사용자로부터 입력을 잘 받은 것을 볼 수 있다.

그 이유는,
```c
scanf("%d", &i);
```
를 실행하여 사용자로부터 수를 입력 받게 된다면 역시 `stdin`에는 `\n`이 남아있게 된다. 

그리고
```c
scanf("%s", str);
```
를 실행하게 되면 역시 수 데이터를 입력 받는 형식처럼 실질적인 데이터(공백문자가 아닌 것들)가 나오기 전까지 버퍼에 남아 있던 공백문자들은 무시하고 실질적인 문자가 입력이 된다면 그 다음부터 등장하게 되는 공백문자에서는 종료하게 된다.
즉, 기존에 1을 입력했을 때 남아있던 `\n`은 사라지고, `aasdfdasfads`를 입력하고 난 후, 엔터를 쳤을 때 들어가는 `\n`을 인식하게 된다는 것이다.

결론적으로, `%s`나 `%d` 그리고 다른 모든 수 데이터를 입력받는 형식은 버퍼에 남아있는 공백 문자에 신경쓰지 않고 사용할 수 있다.

> [!info]
> 그렇다고 해서 %s를 입력받은 후 버퍼가 완벽히 깨끗해지는 것이 아니다. 개행 문자는 뒤에 남아있다.

하지만 `%c`를 이용할 때는 버퍼에 무엇이 남아있는지 잘 고려해야 한다.

### 문자열에서 버퍼 문제
```cpp
/* 마지막 stdin 예제 */
#include <stdio.h>
int main() {
	char str1[10], str2[10];
	
	printf("문자열을 입력하세요 : ");
	scanf("%s", str1);
	printf("입력한 문자열 : %s \n", str1);
	
	printf("문자열을 입력하세요 : ");
	scanf("%s", str2);
	printf("입력한 문자열 : %s \n", str2);
	
	return 0;
}
```
성공적으로 컴파일 했다면
```
문자열을 입력하세요 : hello
입력한 문자열 : hello 
문자열을 입력하세요 : baby
입력한 문자열 : baby
```
잘 실행되는 것을 볼 수 있지만,
다음과 같이 입력하면
```
문자열을 입력하세요 : hello baby
입력한 문자열 : hello 
문자열을 입력하세요 : 입력한 문자열 : baby
```
결과가 제대로 나오지 않는 걸 확인할 수 있다.

왜그런걸까? 먼저 hello baby를 입력했을 때 `stdin`의 상태를 보자.
`stdin`에는 `hello baby\n`가 들어갔을 것이다.

그 다음 `scanf`함수는 `stdin`으로부터 의미가 있는 문자(공백문자를 제외한 나머지 문자)가 나올 때까지 모든 공백 문자들을 무시한다. 위의 경우 `stdin`에서 처음에 공백 문자가 하나도 없으므로 바로 `stdin`으로부터 데이터를 가져온다.

가져오다가 공백 문자를 만나게 되면 입력을 중지하는데, hello와 baby 사이의 `' '`이 공백 문자의 역할을 하기 때문에 `str1`에는 `hello`까지만 입력이 된다.

그러면 `stdin`은 ` baby\n`(앞에 공백 포함)가 남아있을 것이다.

그 다음 두번째 `scanf`에서 처음에 공백문자는 무시하고 `b`를 발견하고 `str2`에 입력을 쭉 받기 시작한다. 그러다가 마지막에 공백 문자인 `\n`을 보고 입력을 중지한다. 따라서 `stdin` 에는 `\n`만 덩그러니 남아있게 된다.

### 문제 해결
```c
/*
버퍼 비우기

주의하실 점은 반드시 MS 계열의 컴파일러로 컴파일 해주세요. 즉, Visual Studio
계열의 컴파일러로 말이죠. 이 말이 무슨 말인지 모르면 그냥 늘 하던대로 하면
됩니다.

gcc 에서는 정상적으로 작동되지 않는 위험한 코드 입니다.
*/
#include <stdio.h>
int main() {
	int num;
	char c;
	
	printf("숫자를 입력하세요 : ");
	scanf("%d", &num);
	
	fflush(stdin);
	
	printf("문자를 입력하세요 : ");
	scanf("%c", &c);
	return 0;
}
```

```c
fflush(stdin);
```
`fflush`를 통해 버퍼를 지울 수 있다.

하지만 위 코드는 추천하지 않는다. 왜냐하면 `fflush`가 표준으로 '무슨 역할을 한다'라고 정해진 것이 아니기 때문이다.

다시 말해 `Visual Studio`에선 `fflush`함수가 버퍼를 비우는 훌륭한 역할을 하지만 다른 것 - 예를 들면 `gcc` 같은 데서는 이러한 작업을 하지 않을 가능성이 매우 크다.

> [!info]
> Visual Studio 2015 부터는 표준을 따라서 fflush가 위와 같이 작동하지 않는다.

```c
/* getchar 함수 이용 */
#include <stdio.h>
int main() {
	int num;
	char c;
	
	printf("숫자를 입력하세요 : ");
	scanf("%d", &num);
	
	getchar();
	
	printf("문자를 입력하세요 : ");
	scanf("%c", &c);
	
	return 0;
}
```
성공적으로 컴파일 했다면
```
숫자를 입력하세요 : 1
문자를 입력하세요 : c
```

제대로 작동하는 것을 확인할 수 있다.
`getchar()`는 `stdin`에서 한 문자를 읽어와서 그 값을 반환하는 함수이다. 이 함수를 호출함으로써 `\n`을 `stdin`에서 읽어와 지워버릴 수 있는 것이다.

하지만 위 방법도 문제가 있다. 만약 버퍼에 한 문자만 남겨져 있는 것이 아니면 어떨까?

```c
/* c 에 무엇이 들어가는지 살짝 보아야 하므로 코드를 약간 수정했습니다 */
#include <stdio.h>
int main() {
	int num, i;
	char c;
	
	printf("숫자를 입력하세요 : ");
	scanf("%d", &num);
	
	getchar();
	
	printf("문자를 입력하세요 : ");
	scanf("%c", &c);
	
	printf("입력한 문자 : %c", c);
	return 0;
}
```
여기서 숫자을 입력할 때 `123abc`를 쳐보면 다음과 같이 나온다.
```
숫자를 입력하세요 : 123abc
문자를 입력하세요 : 입력한 문자 : b
```
왜냐하면 `%d`가 `123`까지 읽은 후 `getchar()`가 `a`를 읽었기 때문이다.

### 되도록 `%c`를 사용하지 말자.

제일 깔끔한 방법은 `scanf`에서 `%c`를 사용하지 않는 것이다.
만약 문자 하나만을 입력 받는 프로그램을 만드려면 `scanf`에서 `%s` 형태로 문자열을 입력 받은 뒤에 맨 앞의 한 문자만 취하는 식으로 만들자.
