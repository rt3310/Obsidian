```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;

public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
class Derived : public Base {
	std::string s;

public:
	Derived() : s("파생"), Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
int main() {
	std::cout << " === 기반 클래스 생성 ===" << std::endl;
	Base p;
	
	p.what();
	
	std::cout << " === 파생 클래스 생성 ===" << std::endl;
	Derived c;
	
	c.what();
	
	return 0;
}
```
위 코드를 성공적으로 컴파일했다면,
```
 === 기반 클래스 생성 ===
기반 클래스
기반
 === 파생 클래스 생성 ===
기반 클래스
파생 클래스
파생
```
`Base`에서 `what`을 호출하면 당연히 `Base`의 `what`이 실행되어서 '기반'이라고 나오고, `Base`를 상속받는 `Derived` 클래스에서 `what`을 호출하면, `Derived`의 `what`이 `Base`의 `what`을 override해서 `Derived`의 `what`이 호출되게 된다.

이번에는 코드를 약간 변형해보자.
```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;
	
public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
class Derived : public Base {
	std::string s;
	
public:
	Derived() : s("파생"), Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
int main() {
	Base p;
	Derived c;
	
	std::cout << "=== 포인터 버전 ===" << std::endl;
	Base* p_c = &c;
	p_c->what();
	
	return 0;
}
```
성공적으로 컴파일 했다면,
```
기반 클래스
기반 클래스
파생 클래스
=== 포인터 버전 ===
기반
```
이번에는 `Derived`의 객체 `c`를 `Base` 객체를 가리키는 포인터에 넣었다.

```cpp
Base* p_c = &c;
```
`Derived` 객체 `c`도 어떻게 보면 `Base` 객체이기 때문에 `Base` 객체를 가리키는 포인터가 `c`를 가리켜도 무방하다.
![[Pasted image 20260731000454.png]]
그 대신 `p`는 엄연히 `Base` 객체를 가리키는 포인터이다. 따라서, `p`의 `what`을 실행한다면 `p`는 당연히 '`Base`의 `what`을 실행해주어야 겠구나'하고, `Base`의 `what`을 실행해서, `Base`의 `what`은 `Base`의 `s`를 출력하게 된다.

이러한 형태의 캐스팅을 **업캐스팅**이라고 부른다.
![[Pasted image 20260731000608.png]]

그럼 다운캐스팅도 있을까? 다음 코드를 컴파일 해보자.
```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;
	
public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
class Derived : public Base {
	std::string s;
	
public:
	Derived() : s("파생"), Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
int main() {
	Base p;
	Derived c;
	
	std::cout << "=== 포인터 버전 ===" << std::endl;
	Derived* p_p = &p;
	p_p->what();
	
	return 0;
}
```
컴파일한다면 아래와 같은 오류 메시지가 나온다.
```
error C2440: 'initializing' : cannot convert from 'Base *' to 'Derived *'
```

이는
![[Pasted image 20260731000719.png]]
만일 `Derived*` 포인터가 `Base` 객체를 가리킨다고 했을 때, `p_p->what()`을 하게 된다면 `Derived`의 `what` 함수가 호출되어야 하는데, 이는 불가능하기 때문이다.
왜냐면, `p_p`가 가리키는 객체는 `Base` 객체이므로 `Derived`에 대한 정보가 없다. 따라서, 이와 같은 문제를 막기 위해서 컴파일러 상에서 함부로 다운 캐스팅 하는 것을 금지하고 있다.

그럼 만약 다음과 같은 상황은 어떨까?
```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;
	
public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
class Derived : public Base {
	std::string s;
	
public:
	Derived() : s("파생"), Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
int main() {
	Base p;
	Derived c;
	
	std::cout << "=== 포인터 버전 ===" << std::endl;
	Base* p_p = &c;
	
	Derived* p_c = p_p;
	p_c->what();
	
	return 0;
}
```
컴파일 하면 전과 같은 에러가 뜬다.

하지만 우리는 `p_p`가 가리키는 것이 `Derived`라는 것을 알고 있다. 때문에 비록 `Base *` 포인터를 다운캐스팅 함에도 불구하고 `p_p`가 실제로는 `Derived` 객체를 가리키기 때문에
```cpp
Derived* p_c = p_p;
```
를 해도 전혀 문제가 없다.

위 코드의 타입 변환을 위해서는 아래처럼 강제적으로 변환을 하면 된다.
```cpp
Derived* p_c  = static_cast<Derived*>(p_p);
```
약간은 위험하지만(만약 `p_p`가 `Derived` 객체를 가리키지 않는다면), 컴파일 에러르 발생시키지 않고 성공적으로 컴파일 할 수 있다.
그렇다면 만일 `p_p`가 `Base`객체를 가리키는데 강제적으로 타입 변환을 해서 `what`을 실행하면 어떻게 될까?

```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;
	
public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
class Derived : public Base {
	std::string s;
	
public:
	Derived() : s("파생"), Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() { std::cout << s << std::endl; }
};
int main() {
	Base p;
	Derived c;
	
	std::cout << "=== 포인터 버전 ===" << std::endl;
	Base* p_p = &p;
	
	Derived* p_c = static_cast<Derived*>(p_p);
	p_c->what();
	
	return 0;
}
```
위 코드를 컴파일하고 실행시켜 보면 런타임 에러가 나는 것을 볼 수 있다.

이런 강제적인 다운 캐스팅의 경우, 컴파일 타임에서 오류를 찾아내기 힘들기 때문에 다운 캐스팅은 작동이 보장되지 않는 한 매우 권장하지 않는다.

### dynamic_cast
이러한 캐스팅에 따른 오류를 미연에 방지하기 위해, C++에서는 상속 관계에 있는 두 포인터들 간에 캐스팅을 해주는 `dynamic_cast`라는 것을 지원한다. 이를 사용하는 방법은 `static_cast`와 거의 동일하다.

하지만 위의 코드의 경우 컴파일 하면,
```cpp
Derived* p_c = dynamic_cast<Derived*>(p_p);
```
다음과 같이 캐스팅 할 수 없다는 컴파일 에러가 발생한다.
```
test.cc: In function 'int main()':
test.cc:27:44: error: cannot dynamic_cast 'p_p' (of type 'class Base*') to type 'class Derived*' (source type is not polymorphic)
   Derived* p_c = dynamic_cast<Derived*>(p_p);
```

> [!info]
> dynamic_cast를 위해서는 virtual 키워드가 하나 이상 선언되어 있는 class여야 한다.

### virtual
```cpp
#include <iostream>

class Base {

public:
	Base() { std::cout << "기반 클래스" << std::endl; }
	
	virtual void what() { std::cout << "기반 클래스의 what()" << std::endl; }
};
class Derived : public Base {

public:
	Derived() : Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() { std::cout << "파생 클래스의 what()" << std::endl; }
};
int main() {
	Base p;
	Derived c;
	
	Base* p_c = &c;
	Base* p_p = &p;
	
	std::cout << " == 실제 객체는 Base == " << std::endl;
	p_p->what();
	
	std::cout << " == 실제 객체는 Derived == " << std::endl;
	p_c->what();
	
	return 0;
}
```
성공적으로 컴파일 했다면
```
기반 클래스
기반 클래스
파생 클래스
 == 실제 객체는 Base == 
기반 클래스의 what()
 == 실제 객체는 Derived == 
파생 클래스의 what()
```
위와 같이 나온다.
여기서 `p_p`와 `p_c` 모두 `Base` 객체를 가리키는 포인터라서 `p_p->what()`과 `p_c->what()`을 하면 모두 `Base` 객체의 `what()` 함수가 실행돼서 둘 다 '기반'이라고 출력되어야만 했다.

그런데, 실제 `p_p`와 `p_c`가 무엇과 결합해 있는지 아는 것처럼(`p_p`는 `Base` 객체를 가리키고, `p_c`는 `Derived` 객체를 가리키는) 이에 따른 적절한 `what` 함수를 호출해준 것이다.

이렇게 할 수 있는 이유는 바로 `virtual` 키워드 때문이다.
`virtual` 키워드를 선언하면 컴파일 시에 어떤 함수가 실행될 지 정해지지 않고, 런타임 시에 정해지도록 한다. 이를 **동적 바인딩(dynamic binding)** 이라고 부른다.

또한 `virtual` 키워드가 붙은 함수를 **가상 함수(virtual function)** 라고 부른다.

### override
```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;
	
public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	virtual void what() { std::cout << s << std::endl; }
};
class Derived : public Base {
	std::string s;
	
public:
	Derived() : s("파생"), Base() { std::cout << "파생 클래스" << std::endl; }
	
	void what() override { std::cout << s << std::endl; }
};
```
C++11에서는 파생 클래스에서 기반 클래스의 가상 함수를 override하는 경우, `override` 키워드를 통해 명시적으로 나타낼 수 있다.
```cpp
void what() override { std::cout << s << std::endl; }
```
위 경우 `Derived` 클래스의 `what` 함수는 `Base` 클래스의 `what` 함수를 override 하므로, `override` 키워드를 통해 이를 알려주고 있다.

`override` 키워드를 사용하게 되면, 실수로 override 하지 않는 경우를 막을 수 있다. 예를 들어,
```cpp
#include <iostream>
#include <string>

class Base {
	std::string s;
	
public:
	Base() : s("기반") { std::cout << "기반 클래스" << std::endl; }
	
	virtual void incorrect() { std::cout << "기반 클래스 " << std::endl; }
};
class Derived : public Base {
	std::string s;
	
public:
	Derived() : Base(), s("파생") {}
	
	void incorrect() const { std::cout << "파생 클래스 " << std::endl; }
};
int main() {
	Base p;
	Derived c;
	
	Base* p_c = &c;
	Base* p_p = &p;
	
	std::cout << " == 실제 객체는 Base == " << std::endl;
	p_p->incorrect();
	
	std::cout << " == 실제 객체는 Derived == " << std::endl;
	p_c->incorrect();
	return 0;
}
```
성공적으로 컴파일 했다면
```
기반 클래스
기반 클래스
 == 실제 객체는 Base == 
기반 클래스 
 == 실제 객체는 Derived == 
기반 클래스
```
와 같이 `incorrect()` 함수가 제대로 override 되지 않았음을 알 수 있다. 그 이유는 `Base`의 `incorrect()`는 상수 함수이고 `Derived`의 `incorrect()`는 아니기 때문이다.

따라서 컴파일러 입장에서 두 함수는 다른 함수로 간주된다. 하지만 다음과 같이 `override` 키워드를 쓴다면
```cpp
void incorrect() const override { std::cout << "파생 클래스 " << std::endl; }
```

다음과 같이 `Derived`의 `incorrect()`가 `override` 한다고 써있지만, 실제로는 아무것도 override 하지 않는다고 오류가 발생하게 된다.
```
test.cc:19:8: error: 'void Derived::incorrect() const' marked 'override', but does not override
```
여기서 `const` 키워드를 지워준다면 제대로 동작할 것이다.
