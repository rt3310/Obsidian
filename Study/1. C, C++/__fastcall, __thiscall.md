`__fastcall`은 **레지스터를 사용해 함수 호출 속도를 극대화**하기 위한 규약이고, `__thiscall`은 **C++ 객체 지향 메서드에서 `this` 포인터를 효율적으로 전달**하기 위해 설계된 규약이다.

## `__fastcall` (Fast Call)

메모리(스택)보다 접근 속도가 훨씬 빠른 **CPU 내부 레지스터**를 매개변수 전달에 직접 활용하는 방식이다.
- **사용**: 짧고 빈번하게 호출되어 스택 메모리 접근 오버헤드를 줄이고 실행 속도를 극한으로 높여야 하는 연산 함수나 커널 내부 코드에 쓰입니다.
- **동작 방식 (x86 기준)**
    1. **첫 번째, 두 번째 인자**(4바이트 이하): 스택에 넣지 않고 **`ECX`와 `EDX` 레지스터**에 직접 대입한다.
    2. **세 번째 인자부터**: 기존 규약들처럼 스택에 `Right-to-Left` 순서로 푸시한다.
    3. **스택 정리**: 피호출자(Callee)가 `RET N`으로 스택을 정리한다.
- **이름 장식**: `@함수명@인자바이트크기` (예: `@add@12`)
    
```asm
; int __fastcall add(int a, int b, int c) 호출 시
push 3          ; 세 번째 인자 (c) -> 스택에 PUSH
mov edx, 2      ; 두 번째 인자 (b) -> EDX 레지스터에 즉시 할당
mov ecx, 1      ; 첫 번째 인자 (a) -> ECX 레지스터에 즉시 할당
call @add@12    ; 함수 호출 (스택 정리는 add 내부의 ret 4가 처리)
```

## `__thiscall` (This Call)

C++ 클래스의 **비정적 멤버 함수(Non-static member function)** 를 호출할 때 컴파일러가 기본(Default)으로 적용하는 호출규약이다.
- **사용**: C++ 객체의 메서드를 호출할 때, 함수 내부에서 어떤 인스턴스의 멤버 변수에 접근해야 하는지 알 수 있도록 객체의 메모리 주소(`this` 포인터)를 전달할 때 사용됩니다.
- **동작 방식 (x86 기준)**:
    1. **`this` 포인터 전달**: 호출 대상 객체의 주소(`this`)를 **`ECX` 레지스터**에 담아 전달한다.
    2. **일반 매개변수 전달**: 메서드가 받는 일반 인자들은 스택에 `Right-to-Left` 순서로 푸시한다.
    3. **스택 정리**: 피호출자(Callee)가 스택을 정리한다. (단, 멤버 함수가 `printf`처럼 가변 인자를 사용하면 예외적으로 `__cdecl`로 전환되어 호출자가 스택을 정리한다.)

```asm
; myObject.SetAge(10, 20) 호출 시
push 20                 ; 두 번째 인자
push 10                 ; 첫 번째 인자
lea ecx, [myObject]     ; myObject의 주소(this 포인터)를 ECX 레지스터에 저장
call CPlayer::SetAge   ; 메서드 호출
```

## 핵심 비교 표

|구분|`__fastcall`|`__thiscall`|
|---|---|---|
|**주 목적**|인자 전달 속도 최적화|C++ 객체의 `this` 포인터 전달|
|**레지스터 활용**|`ECX` (1번째 인자), `EDX` (2번째 인자)|`ECX` (`this` 포인터 전용)|
|**스택 활용**|3번째 인자부터 스택 전달|모든 일반 매개변수를 스택 전달|
|**스택 정리**|피호출자 (Callee)|피호출자 (Callee)|

> [!info] **64비트(x64)와의 연관성**
> x86 32비트 시대에는 속도를 내기 위해 `__fastcall`을 별도로 선언해야 했지만, **x64 환경으로 넘어오면서 기본 호출규약 자체가 레지스터를 대량 활용하는 방식으로 통합**되었다. (Windows x64에서는 `RCX`, `RDX`, `R8`, `R9` 4개의 레지스터를 기본으로 사용)
