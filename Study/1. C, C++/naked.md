naked는 엄밀히 말해 호출규약이 아니라, 컴파일러에게 "이 함수에는 프롤로그(Prologue)와 에필로그(Epilogue) 코드를 자동으로 생성하지 마라"고 지시하는 속성이다.

### 프롤로그와 에필로그란?
컴파일러는 일반적인 C/C++ 함수를 만들 때, 함수 시작과 끝에 스택 프레임을 형성하고 복구하는 어셈블리 코드를 자동으로 삽입한다.

- **프롤로그 (함수 시작)**: 이전 스택 프레임 저장(`push ebp`), 새로운 스택 프레임 생성(`mov ebp, esp`), 지역 변수 메모리 공간 확보(`sub esp, N`).
- **에필로그 (함수 종료)**: 스택 프레임 복구(`mov esp, ebp`, `pop ebp`), 호출자로 복귀(`ret`).

### `naked` 속성의 동작 방식
`__declspec(naked)`를 붙이면 컴파일러가 위와 같은 프롤로그/에필로그를 **전혀 생성하지 않는다.**

```cpp
// MSVC 기준 naked 함수 정의
void __declspec(naked) CustomFunction() {
    __asm {
        // 프롤로그, 에필로그, ret 명령어까지 
        // 모든 어셈블리 코드를 개발자가 직접 작성해야 함
        push ebp
        mov ebp, esp
        
        ; ... 함수 로직 ...
        
        pop ebp
        ret
    }
}
```

### 언제 사용되나?
- **운영체제 커널 개발**: 인터럽트 핸들러(Interrupt Handler) 구현 시 레지스터 상태를 한 치의 오차도 없이 보존해야 할 때
- **문맥 교환 (Context Switching)**: 스레드나 프로세스 전환을 정밀하게 제어해야 하는 시스템/임베디드 레벨 코드
- **API 후킹 및 인라인 어셈블리**: 레지스터나 스택 메모리를 1바이트 단위로 직접 조작해야 하는 보안, 리버스 엔지니어링, 시스템 라이브러리 개발
