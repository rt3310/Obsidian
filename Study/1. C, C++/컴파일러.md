## 컴파일러 배경

### GCC (GNU Compiler Collection)
GCC는 1987년에 리처드 스톨먼이 GNU 프로젝트의 일환으로 만들었다. 당시 유닉스 시스템의 컴파일러들이 모두 상업용이었는데, 자유 소프트웨어 운동의 일환으로 "누구나 자유롭게 쓸 수 있는 컴파일러"를 만들자는 취지였다.

처음엔 C 컴파일러로 시작했지만, 지금은 C++, Objective-C, Fortran, Ada, Go 등 많은 언어를 지원하는 거대한 컴파일러 모음집이 됐다. 이름에 "Collection"이 붙은 이유가 바로 이것이다.

리눅스 커널 개발에 핵심적으로 사용되면서 오픈소스 세계의 표준 컴파일러로 자리잡았고, 지금도 전 세계 수많은 개발자들이 기여하고 있다.

### Clang (C Language Family Frontend)
Clang은 2007년 애플이 주도해서 시작한 프로젝트이다.

당시 GCC는 너무 복잡하고 무거워서 IDE와 통합하기 어려웠다. 에러 메세지도 불친절하고, 컴파일 속도도 느렸다. 애플은 Xcode에 더 나은 개발 경험을 제공하고 싶었고, 그래서 처음부터 "모듈화"와 "IDE 친화적"을 목표로 Clang을 설계했다.

Clang은 LLVM이라는 컴파일러 인프라 위에 구축됐는데, 이 LLVM 덕분에 최적화 성능이 매우 좋다. 직므은 macOS와 iOS 개발의 기본 컴파일러이고, 구글도 안드로이드 NDK에서 Clang을 기본으로 채택했다.

### MSVC (Microsoft Visual C++)
MSVC는 마이크로소프트가 1993년부터 개발해온 컴파일러이다. Visual Studio와 완벽하게 통합돼 있어서 Windows 개발자들에게는 가장 친숙한 도구이다.

초기에는 표준 준수가 아쉬웠지만, 최근 몇 년간 엄청난 발전을 이뤘다. 특히 C++11 이후 모던 C++ 표준을 적극적으로 지원하면서 표준 준수도에서 GCC, Clang과 어깨를 나란히 하게 되었다.

윈도우 플랫폼에 최적화되어 있고, Windows API와의 통합이 완벽해서 윈도우 네이티브 애플리케이션 개발에는 최고의 선택이다.

## 컴파일러 아키텍처 & 내부 구조

### 컴파일 과정 기본 단계
1. 전처리(Preprocessing)
	- `#include`, `#define` 같은 전처리 지시자를 처리
2. 구문 분석(Parsing)
	- 소스코드를 읽어서 추상 구문 트리(AST)로 변환
3. 의미 분석(Semantic Analysis)
	- 타입 체크, 변수 선언 확인 등을 수행
4. 중간 코드 생성 (IR Generation)
	- 플랫폼 독립적인 중간 표현으로 변환
5. 최적화(Optimization)
6. 코드 생성(Code Generation)
	- 실제 기계어나 어셈블리 코드 생성
7. 링킹(Linking)
	- 여러 오브젝트 파일을 하나의 실행 파일로 합침

### GCC 아키텍처
GCC는 전통적인 3단계 컴파일러 구조를 가지고 있다.

Frontend → Middle-end → Backend

Frontend는 언어별로 다르게 구현돼 있다.
C++ 프론트엔드는 `g++`이고, 이게 소스 코드를 GENERIC이라는 중간 표현으로 변환한다. 그 다음 GIMPLE 이라는 더 단순한 형태로 변환되고, 이게 Middle-end에서 최적화 된다.

Backend는 타겟 플랫폼 별로 다르게 구현되어 있어서 x86, ARM, MIPS 등 다양한 아키텍처를 지원한다. 이런 구조 덕분에 새로운 언어나 플랫폼을 추가하기 쉽다.

### Clang/LLVM 아키텍처
Clang은 LLVM 위에 구축된 프론트엔드이다. LLVM의 구조는 정말 혁신적이다.

Clang (Frontend) → LLVM IR → LLVM Optimizer → LLVM Backend

Clang은 C/C++/Objective-C 코드를 파싱해서 LLVM IR(Intermediate Representation)이라는 중간 표현으로 변환한다.
이 LLVM IR이 핵심인데, 플랫폼 독립적이면서도 최적화하기 쉬운 형태로 설계됐다.

LLVM의 가장 큰 장점은 **모듈화**이다. 각 단계가 명확하게 분리돼 있어서 재사용하기 쉽고, IDE나 다른 도구와 통합하기도 편하다. 그래서 Xcode, Visual Studio Code 같은 IDE들이 Clang을 활용해서 코드 자동완성, 리팩토링 같은 기능을 제공할 수 있다.

### MSVC 아키텍처
MSVC는 Microsoft의 독자적인 컴파일러 아키텍처를 사용한다. 전통적인 구조를 따르면서도 윈도우 플랫폼에 최적화되어있다.

C/C++ Frontend → Optimizer → Code Generator

MSVC의 특징은 Visual Studio와의 긴밀한 통합이다. IntelliSense, Debugger, Profiler 등이 컴파일러와 완벽하게 연동돼서 개발 경험이 좋다.

최근에는 Clang 과의 호환성도 높여서 `clang-cl`이라는 Clang 기반 컴파일러도 제공하고 있다. MSVC의 ABI(Application Binary Interface)를 유지하면서 Clang의 장점을 활용할 수 있게 한 것이다.

## 컴파일러 별 핵심 특징

### 표준 준수도 (Standard Compliance)
C++ 표준을 얼마나 잘 따르는지는 중요한 문제이다. 표준을 잘 지키지 않으면 다른 플랫폼으로 이식할 때 문제가 생기기 때문이다.

#### Clang
Clang이 표준 준수도에서 가장 앞서있다. 새로운 C++ 표준이 나오면 가장 빠르게 지원하는 편이고, 표준의 세부 사항까지 정확하게 구현하려고 노력한다. C++20, C++23의 최신 기능들도 가장 먼저 지원하는 경우가 많다.

#### GCC
GCC도 표준 준수도가 아주 좋다. Clang과 거의 비슷한 수준으로 표준을 지원하고, 때로는 실험적 기능을 먼저 제공하기도 한다. 특히 GNU 확장 기능들이 많아서 시스템 프로그래밍에 유용하다.

#### MSVC
MSVC는 과거에는 표준 준수도가 좀 아쉬웠는데, 최근 몇 년간 엄청나게 개선됐다. Visual Studio 2019부터는 C++17을 완전히 지원하고, C++20 지원도 빠르게 추가되고 있다. 하지만 여전히 일부 GNU 확장이나 Clang 확장은 지원하지 않는다.

> [!tip]
> 크로스 플랫폼 프로젝트라면 세 컴파일러 모두에서 테스트하는 것이 좋다. 특히 템플릿 메타프로그래밍이나 최신 C++ 기능을 많이 쓴다면 더욱 그렇다.

## GCC vs G++

### GCC(GNU Compiler Collection & GNU C Compiler)
본래 C언어용 컴파일러로 시작하여, GNU C Compiler의 약자였으나, 2.9 버전에 이르러 C언어 뿐 아니라 Objective C, Pascal, Ada 등과 같은 언어를 지원하게 되면서 GNU Compiler Comllection으로 이름이 변경되었다.
Linux, Windows 등 수많은 운영체제를 지원하여 높은 호환성을 가지고 있고, 자동 레지스터 할당, 반복적인 코드 제거, 상수 곱셈 최적화 등 많은 최적화를 수행하는 컴파일러이다.

### G++ (GNU C++ Compiler)
C++용 컴파일러이다.

### GCC vs G++
| GCC                           | G++                      |
| ----------------------------- | ------------------------ |
| .c파일과 .cpp 파일을 각각 C와 C++로 컴파일 | .c파일과 .cpp파일 모두 C++로 컴파일 |
| C 라이브러리와 링크됨                  | C++ 라이브러리에 링크됨           |
| 미리 정의된 매크로가 거의 없음             | 몇 가지 추가 매크로 존재           |

### 주의
C++로 작성된 .cpp 파일을 GCC로 컴파일 시 GCC가 .cpp 파일을 컴파일 한 후 C 라이브러리로 링크하기 때문에 링크 에러가 발생할 수 있다.
