### 파일 출력
```c
/* a.txt 에 내용을 기록한다. */
#include <stdio.h>

int main() {
	FILE *fp;
	fp = fopen("a.txt", "w");
	
	if (fp == NULL) {
		printf("Write Error!!\n");
		return 0;
	}
	
	fputs("Hello World!!! \n", fp);
	
	fclose(fp);
	return 0;
}
```
위 코드를 실행시키면 `a.txt` 파일이 생성된 것을 볼 수 있다.

우리가 하드디스크에 저장되어 있는 파일들을 자유롭게 이용할 수 있다고는 하나, 이를 쓰는 과정은 매우 복잡할 것이다. 왜냐하면 파일을 새로 만든다고 쳐도, 하드디스크 어떤 부분에 파일을 새로 만들어야 할지, 얼마나 크게 파일을 만들 수 있는지 등의 모든 것을 고려해야 한다.
다행히 운영체제에서 이를 알아서 해준다.

`fopen` 함수는 위에서 말한 '운영체제가 알아서 해주는 부분'을 처리한다. `fopen` 함수는 우리가 지정한 파일(a.txt)와 소통할 수 있도록 스트림을 만들어 준다.

### 스트림
![[154733414D1894062D76CF.webp]]
우리가 `printf` 함수를 이용할 때 어떤 작업이 컴퓨터에서 내부적으로 처리되는지 생각해보자.

먼저, 출력할 문자열을 구성해야하고 이를 모니터에 전달해서 출력하라는 명령을 내리게 해야한다.
이를 쉽게할 수 있는 이유는 **스트림**에 있다. 스트림은 이 두 개의 완전히 다른 장치들을 이어주는 파이프라고 보면 된다.
이러한 스트림은 우리가 직접 구현해야 되는 것이 아니라 운영체제가 스스로 처리해 주는 것이다.
만약 우리가 모니터와 잇는 스트림을 이용한다면 운영체제는 모니터에 맞는 명령을 내릴 것이고, 키보드와 잇는 스트림을 이용한다면 운영체제가 키보드에 맞는 명령을 알아서 내릴 것이다.

> [!info]
> 스트림을 정확히 표현하면 '추상화된 장치(abstract devices)'라고 말할 수 있다.
> 왜냐하면 여러 가지 주변 장치들(모니터, 키보드, 하드 디스크)을 추상화 시켜서 사용자가 마치 동일한 장치에 접근하는 것처럼 사용할 수 있게 만들었기 때문이다.
> 스트림은 마치 책장과 같이 만들었다. 책장에 책을 끼우거나 빼는 것처럼 데이터를 순차적으로 쭉 나열해서 데이터의 끝까지 차례대로 읽어들일 수 있도록 만들었다.

따라서 만일 우리가 모니터에 A를 출력하고 싶다면 단순히 스트림에 A를 넣으면 된다. 이렇게 스트림으로 전달된 문자 A는 운영체제에 의해 알아서 모니터에 명령을 내려서 A를 출력하게 된다.
마찬가지로 키보드에서 문자를 받고 싶다면 스트림을 타고 무슨 문자가 오는지에만 관심을 가지면 된다. 우리가 피보드에 무언가를 입력했다면 운영체제에서 알아서 잘 해석 한 다음 우리가 이해할 수 있는 데이터로 만들어서 스트림에 전달하기 때문이다.

모니터와 키보드에 대한 스트림은 표준 스트림(standard stream)이라 해서 프로그램이 실행될 때 자동으로 생성된다.

![[1438BA514D189A2D0FA2F2.webp]]

위 그림에도 나와있듯 모니터에 대한 스트림은 `stdout`이고, 키보드에 대한 스트림은 `stdin`이다. (그 외에 `stderr` 라는 표준 오류 스트림이란 것이 있는데 `stdout`하고 거의 동일하다고 보면 된다. 단지, 오류 메세지를 출력하는 스트림이다)

```c
FILE *fp;
fp = fopen("a.txt", "w");
```
이렇게 해서 스트림을 만들었으면 `fopen`함수는 만든 스트림을 가리키는 포인터를 반환한다.
스트림에 관한 정보는 `FILE` 구조체에 들어가 있다. 이제, 우리는 `fp`를 가지고 파일을 사용할 수 있게 되었다.
그런데, `fopen`에서 두 번째 인자로 "w"를 전달했는데, 이는 파일에 오직 '쓰기'만 가능하게 하겠다라는 의미이다. 다시 말해 스트림인데도 출력 스트림만 만들어 놓은 것이다

이렇게 출력만 하게 했다면 당연히 파일에 쓰기만 할 수 있다. 파일에서 데이터를 읽는 작업은 불가능하다.

`fopen`에서 "w"로 전달하면, 첫번째 인자로 전달된 이름의 파일이 존재하지 않는다면 아무 내용이 없는 파일을 새로 만들거나, 동일한 이름의 파일이 존재한다면 그 내용을 다 지워버리게 된다.

```c
if (fp == NULL) {
	printf("Write Error!!\n");
	return 0;
}
```
파일이 어떠한 이유에서라든 열지 못한 경우 `fopen` 함수는 `NULL`을 반환한다. `fopen`이 실패하는 경우는 그리 많지 않으므로 이 부분을 생략하는 경우가 가끔 있는데, 만일 `fopen`이 실패하게 되었을 경우 이렇게 검사하지 않는다면 소스 뒷부분에서 어떠한 문제가 발생할지 모르므로 이렇게 항상 검사하는 것이 중요하다.

```c
fputs("Hello World!!! \n", fp);
```
이제 `fputs`라는 함수로 파일에 기록할 수 있다.

`stdout`은 컴퓨터의 모니터에 해당하는 표준 출력 스트림으로, 만약 두 번째 인자로 `stdout`을 전달하면 콘솔 화면에 문자열이 뜬다.
```c
fputs("Hello World!!! \n", stdout);
```

```c
fclose(fp);
```
마지막으로 연결되었던 스트림을 `fclose`를 통해 닫아주어야 한다. `fclose`로 닫지 않는다면 스트림이 계속 살아 있게 되어서 이 파일은 계속 쓰기 상태로 남아 있게 된다.
이는 프로그램이 종료되기 전까지 이 상태로 계속 남아있기 때문에, 마치 동적 메모리 할당에서 `free`로 메모리를 반환해 주어야 하는 것처럼 스트림도 닫아 주어야 한다.

한가지 재미있는 점은, `fclose`로 표준 스트림들도 닫아버릴 수 있는데
```c
/* stdout 을 닫아버린다 */
#include <stdio.h>
int main() {
	fclose(stdout);
	printf("aaa");
	return 0;
}
```
이렇게 표준 출력 스트림을 닫아버리면 `printf`를 해도 콘솔에 아무 것도 뜨지 않는 걸 볼 수 있다.

### 파일 입력
```c
/* fgets 로 a.txt 에서 내용을 입력 받는다. */

#include <stdio.h>
int main() {
	FILE *fp = fopen("a.txt", "r");
	char buf[20];  // 내용을 입력받을 곳
	if (fp == NULL) {
		printf("READ ERROR !! \n");
		return 0;
	}
	fgets(buf, 20, fp);
	printf("입력받는 내용 : %s \n", buf);
	fclose(fp);
	return 0;
}
```

```c
FILE *fp = fopen("a.txt", "r");
```
이번에는 "r"로 열었는데, 이는 읽기 형식으로 파일을 여는 것이다.

```c
if (fp == NULL) {
	printf("READ ERROR !! \n");
	return 0;
}
```
이전과 마찬가지로 `fp`가 `NULL`인지 아닌지 확인하는데, 특히 읽기 형식으로 파일을 열 때는 더욱 주의해야 한다. 왜냐하면 쓰기 형식으로 파일을 열었을 때는 파일이 존재하지 않는다면 새로 만들었지만, 읽기 형식으로 열 때는 읽어들일 파일이 없다면 `NULL`을 반환하고 스트림을 만들지 않기 때문이다.

```c
fgets(buf, 20, fp);
```
`fgets`함수를 통해 파일로부터 문자열을 입력 받는다.
(입력 받을 변수, 입력 받을 바이트 수, 입력 받는 스트림)을 명시해주면 된다.

`fgets`의 좋은 점은 입력 받는 양을 제한할 수 있다는 점이다. `scanf`의 경우 제한을 두지 않아 할당된 메모리 크기를 넘어버리는 오버플로우가 되는 경우가 있었지만 `fgets`는 이를 방지할 수 있으므로 상당히 안정적이라고 볼 수 있다.

```c
/* 한 글자씩 입력받기*/
#include <stdio.h>

int main() {
	FILE *fp = fopen("a.txt", "r");
	char c;
	
	while ((c = fgetc(fp)) != EOF) {
		printf("%c", c);
	}
	
	fclose(fp);
	return 0;
}
```

여기서 다음 부분을 살펴보자
```c
while ((c = fgetc(fp)) != EOF) {
	printf("%c", c);
}
```
`fgetc`는 `fp`에서 문자 하나를 얻어온다. 즉, 한 문자씩 읽어들이는 것이다. 이 때 문자열 맨 마지막이 `NULL` 문자로 종료를 나타내는 것처럼, 파일의 맨 마지막에는 `EOF`라고 `End Of File`을 나타내는 값인 `-1`이 들어가 있다.
실제로 `EOF`의 원형을 찾아보면
```c
#define EOF (-1)
```
로 `-1`로 선언되어 있다.

따라서 우리는 `c`가 EOF인지 아닌지 비교함을 통해 파일의 끝까지 입력을 받았는지 안받았는지 알 수 있다.

### 파일 위치 지정자
여태까지 파일에서 입력을 받을 때 언제나 파일의 시작 부분에서 끝 부분으로 입력을 받아 나갔다. 즉, 이전에 입력 받았던 데이터는 다시 입력 받지 않는다는 것이다.
이것이 가능한 이유는 **파일 위치 지정자(Position Indicator)** 때문이다. 

만약 `a.txt`에 `abcdefg`가 들어있고 우리가 `fgetc`로 입력을 받는다고 가정하자.
파일을 맨 처음 열었을 때는 파일 위치 지정자는 파일의 맨 첫 부분(`a`)을 가리키고 있다. 그러고 `fgetc`로 입력을 받는다면 파일 위치 지정자는 한 칸 넘어가서 다음에 입력 받을 것을 가리키고 있게 된다. 따라서 `fgetc`를 한 번 더 하면 `a`를 다시 입력 받는 것이 아니라 그 다음인 `b`를 입력 받게 된다. 그리고 또 파일 위치 지정자는 또 한 칸 이동해서 그 다음인 `c`를 가리키고 있을 것이다.

만약 `abcd`까지 파일에서 입력받았는데 다시 처음부터 입력받고 싶다면 어떻게 해야할까?
두 가지 방법이 있는데,
첫 번째는 `fopen`으로 파일을 다른 스트림으로 여는 것이고, 두 번째는 파일 위치 지정자를 맨 앞으로 옮기는 것이다.
```c
#include <stdio.h>
int main() {
  /* 현재 fp 에 abcdef 가 들어있는 상태*/
	FILE *fp = fopen("a.txt", "r");
	fgetc(fp);
	fgetc(fp);
	fgetc(fp);
	fgetc(fp);
	/* d 까지 입력받았으니 파일 위치지정자는 이제 e 를 가리키고 있다 */
	fseek(fp, 0, SEEK_SET);
	printf("다시 파일 처음에서 입력 받는다면 : %c \n", fgetc(fp)); // a
	fclose(fp);
	return 0;
}
```

```c
fseek(fp, 0, SEEK_SET);
```
위 함수를 통해 파일 위치 지정자를 맨 처음으로 돌려버릴 수 있다.
`fseek` 함수는 `fp`를 세 번째 인자로부터 두 번째 인자만큼 떨어진 곳으로 파일 위치 지정자를 돌리는데, 위 경우 `SEEK_SET`으로 부터 0 번째 떨어진 곳, 즉 `SEEK_SET`으로 돌린다고 볼 수 있다.

`SEEK_SET`은 파일의 맨 처음을 일컫는 매크로 상수이다. 따라서 위 함수를 통해 `fp`의 파일 위치 지정자를 맨 처음으로 돌려서 다시 `fgetc`를 했을 때  `a`를 입력받게 된다.

참고로 `SEEK_SET`외에도, 현재 위치를 표시하는 `SEEK_CUR`과 파일의 맨 마지막을 표시하는 `SEEK_END` 상수들이 있다.
