32비트(x86) 환경에서 `__cdecl`, `__stdcall`, `__fastcall` 등이 복잡하게 얽혀 있던 혼란을 끊기 위해, 64비트(x64)에서는 **레지스터 우선 전달(Fastcall 기반) 방식을 기본 규약으로 단일화**했다.

다만, 운영체제 생태계에 따라 **Windows 진영(Microsoft x64 ABI)** 과 **Unix/Linux/macOS 진영(System V AMD64 ABI)** 두 가지 표준으로 나누어 관리되고 있다.

## Windows vs. Linux/macOS x64 호출규약 비교

| 구분             | Microsoft x64 ABI (Windows)                  | System V AMD64 ABI (Linux, macOS, BSD)                     |
| -------------- | -------------------------------------------- | ---------------------------------------------------------- |
| 정수 / 포인터 인자    | **상위 4개** 레지스터 전달 (`RCX`, `RDX`, `R8`, `R9`) | **상위 6개** 레지스터 전달 (`RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9`) |
| 부동소수점 인자       | **상위 4개** 레지스터 전달 (`XMM0` ~ `XMM3`)          | **상위 8개** 레지스터 전달 (`XMM0` ~ `XMM7`)                        |
| 초과 인자 (5/7번째~) | 스택(Stack)을 통해 전달                             | 스택(Stack)을 통해 전달                                           |
| 스택 정돈 단위       | **16바이트 정렬** (16-byte Alignment)             | **16바이트 정렬** (16-byte Alignment)                           |
| 특수 메모리 구조      | **Shadow Space** (32바이트 필수 예약)               | **Red Zone** (128바이트 임시 공간 활용)                             |

## 1. Microsoft x64 ABI (Windows)

Windows 64비트 환경에서는 인자의 순서에 따라 지정된 레지스터가 엄격하게 매핑된다.

- **인자 전달 규칙**:
    - 1번째 인자: `RCX` (부동소수점이면 `XMM0`)
    - 2번째 인자: `RDX` (부동소수점이면 `XMM1`)
    - 3번째 인자: `R8` (부동소수점이면 `XMM2`)
    - 4번째 인자: `R9` (부동소수점이면 `XMM3`)
    - 5번째 인자부터: 스택에 `Right-to-Left` 순서로 push

### Shadow Space (Home Space) 개념

Windows x64의 가장 큰 특징입니다. 인자가 4개 이하라서 레지스터만으로 전부 전달되더라도, 호출자(Caller)는 **함수를 호출하기 직전에 반드시 32바이트(8바이트 × 4개) 크기의 스택 공간을 비워두어야 한다.**

호출당한 함수(Callee)가 최적화를 끄고 디버깅을 하거나, 레지스터가 부족해 인자 값을 메모리에 잠시 저장(Spill)해야 할 때 이 공간을 안전한 백업 영역으로 사용하기 위한 장치이다.

```
; int example(int a, int b, int c, int d, int e); 호출 시 (Windows)
sub rsp, 40         ; Shadow Space(32바이트) + 5번째 인자 공간(8바이트) 확보
mov [rsp+32], 5     ; 5번째 인자(e)는 스택에 저장
mov r9d, 4          ; 4번째 인자(d)
mov r8d, 3          ; 3번째 인자(c)
mov edx, 2          ; 2번째 인자(b)
mov ecx, 1          ; 1번째 인자(a)
call example
add rsp, 40         ; 스택 복구
```

## 2. System V AMD64 ABI (Linux, macOS)

Linux와 macOS 등 Unix 계열 64비트 시스템은 레지스터를 더 적극적으로 활용한다.
- **인자 전달 규칙**:
    - 정수/포인터: `RDI` → `RSI` → `RDX` → `RCX` → `R8` → `R9` (최대 6개)
    - 부동소수점: `XMM0` ~ `XMM7` (최대 8개)
    - 7번째 인자부터: 스택에 push

### Red Zone 개념

`RSP`(스택 포인터) 아래의 **128바이트 공간**을 `RSP`를 바꾸지 않고도 피호출 함수가 임시 데이터 저장용 스크래치 패드로 사용할 수 있도록 ABI 차원에서 보장한다. 이를 통해 스택 포인터를 이동시키는 어셈블리 명령어를 절약할 수 있다.

## x64 표준화가 가져온 주요 변화

1. **`__cdecl`, `__stdcall` 키워드의 비활성화**
    C/C++ 소스코드에 `__stdcall`이나 `__cdecl` 같은 키워드를 명시하더라도, x64 컴파일러는 이를 무시하고 OS의 x64 표준 ABI 규칙 하나로 통합하여 컴파일한다.
    
2. **16바이트 스택 정렬 (16-byte Alignment)**
    SSE/AVX 같은 64비트 SIMD 명령어 세트가 메모리에서 데이터를 빠르게 로드하기 위해 16바이트 정렬을 요구한다. 따라서 `CALL` 명령어가 실행되는 순간 스택 주소(`RSP`)는 항상 16의 배수로 맞춰져 있어야 한다.
