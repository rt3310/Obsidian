
### 공용체
공용체는 구조체와는 달리 메모리를 **공유**한다.

![[1210640D4C14DC693AF455.webp]]
위와 같이 시작주소가 모두 동일하며, `union A`의 경우 `j`의 값을 변경함으로써 `i`의 값을 변경할 수 있고 마찬가지로 `i`의 값을 변경함으로써 `j`의 값을 변경할 수 있다.

```c
/* 공용체 */
#include <stdio.h>
union A {
	int i;
	char j;
};
int main() {
	union A a;
	a.i = 0x12345678;
	printf("%x", a.j); // 78
	return 0;
}
```
`a`의 `j` 멤버 값을 전혀 설정해주지 않았음에도 불구하고 `i`에 `0x12345678`을 대입하자 `j`의 값이 78로 잘 나왔다.

그런데 왜 78이 나왔을까? `0x12`가 나와야되는 것이 아닐까? 그건 컴퓨터가 저장하는 방식에 따라 다르다.
### 빅 엔디안(Big Endian) / 리틀 엔디안(Little Endian)
낮은 주소 값에 상위 비트를 적는 방식을 빅 엔디안, 높은 주소값에 상위 비트를 적는 방식을 리틀 엔디안 이라고 한다.

현재 대부분 x86, x64 프로세서는 리틀 엔디안 방식을 사용하고 있다.

#### 리틀 엔디안(Little Endian)
![[122BC3054C14DC6B87546A.webp]]
리틀 엔디안에서는 위와 같이 1바이트 씩 역으로 보관함을 알 수 있다.

만약 `j`를 `short`형으로 지정했으면 어떻게 출력될까? `0x7856`일까 `0x5678`일까?
```c
#include <stdio.h>
union A {
	int i;
	short j;
};
int main() {
	union A a;
	a.i = 0x12345678;
	printf("%x", a.j);
	return 0;
}
```

```
5678
```
출력해보면 5678로 나오는 것을 볼 수 있다.

![[1522E70D4C14DC6C02944D.webp]]
그 이유는 간단하다.
컴퓨터는 리틀 엔디안 형식으로 이루어져 있다는 것을 알기 때문에 `j`를 출력할 때는 적절히 변환하여 `0x5678`을 출력하게 된다.

### 열거형 (Enum)
```c
#include <stdio.h>
enum { RED, BLUE, WHITE, BLACK };
int main() {
	int palette = RED;
	switch (palette) {
	case RED:
		printf("palette : RED \n");
		break;
	case BLUE:
		printf("palette : BLUE \n");
		break;
	case WHITE:
		printf("palette : WHITE \n");
		break;
	case BLACK:
		printf("palette : BLACK \n");
		break;
	}
}
```

위 코드에서 열거형을 정의한 부분을 살펴보자.
```c
enum { RED, BLUE, WHITE, BLACK };
```
컴파일러는 각 원소에 0부터 차례로 정수 값을 매겨준다.
즉, `RED = 0, BLUE = 1, ..., BLACK = 3`과 같이 말이다.
